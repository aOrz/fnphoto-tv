| A12 | 为同一日期的四张缩略图设置不同延迟，再让其中一张失败；滚走后返回 | 第一张成功即显示，后续逐步补全；慢图或失败不阻止其余图片显示，回收后的旧回调不覆盖新卡片 | NOT RUN |
| A13 | 让详情缩略图先返回、主图延迟；普通浏览和幻灯片各执行一次 | 缩略图可见时转圈消失，主图随后正常替换；幻灯片从主图请求结束后才开始本张完整间隔 | NOT RUN |
| A14 | 下一张照片仍在预取时向右切换，再连续切换、反向返回及退出详情 | 当前图预取不会仅因成为当前项而提前取消；交接期间最多保留当前和下一张两个预取句柄；无错图，退出清理所有预取 | NOT RUN |

A12/A13 需要能分别控制图片响应延迟的本地合成服务或调试代理；现有
`qa_server.py control` 不提供图片延迟开关。无法注入该条件时保留 `NOT RUN`，
不能用普通成功响应代替慢图验收。A14 的请求次数需结合 URL、尺寸和缓存来源判断；
4K 展示与 1080p 预取可能使用不同解码任务，不以“任何情况下只能一个请求”作为判定。

收藏遥控快捷键可用 `adb -s <serial> shell input keyevent 131`（F1）；以当前界面提示为准。不要只看 HTTP 200 就判收藏成功，还要核对响应业务状态及返回列表。

## C. 视频专项（video profile）

先生成 30 秒媒体，启动 video 服务。使用 [README 的 control 命令](README.md#3-可控视频失败场景)显式设置初态。正常 A 为 ID151、正常 B 为 ID314，可控 ID124 的 restored 模式也播放 A。

| ID | 操作 | PASS 判定 / 必留证据 | 本轮状态 |
| --- | --- | --- | --- |
| C01 | 设 `missing`；打开124并开始播放；等待错误，再等待8秒 | 清晰且持久的 HTTP404/视频不存在提示、重试入口及遥控说明；不是无提示黑屏。请求/日志显示404不进入无意义的平台解码重试循环 | NOT RUN |
| C02 | 保持124错误页，Home→正常返回原详情 | 错误状态保留；没有用户点击就不新增124播放请求，不偷偷重播 | NOT RUN |
| C03 | 不离开错误页，control设 `restored`；遥控确定重试 | 新请求恢复正常视频；至少两张不同时间截图的烧录时间码/运动帧推进，证明真实解码而非仅播放器 UI | NOT RUN |
| C04 | 播放A时按媒体播放/暂停键；隔约4秒截图；再次按键恢复 | 暂停期间实际视频帧/烧录时间码不变；恢复后推进。控制器浮层可能变化，应比较视频区域而非机械要求全屏像素一致 | NOT RUN |
| C05 | 在媒体列表或详情切到正常B314，开始播放；再切A151 | A/B内容明确不同，各自有帧推进；旧播放器释放，旧画面/回调不覆盖新媒体 | NOT RUN |
| C06 | 正常视频播放中Back退出 | 回原列表/焦点；无后台持续播放或残留错误；可采集播放器Release日志及 `dumpsys media.resource_manager` 前后对比，无该进程活动codec客户端。此检查不等于长期内存泄漏测试 | NOT RUN |
| C07 | 设 `invalid`；打开124并播放 | HTTP200但非MP4时，有持久、可操作的格式/设备无法播放提示；平台fallback有界，不永远黑屏；仍能重试/切换/退出 | NOT RUN |
| C08 | invalid下重试，在加载/平台fallback时立即切到另一项；等待超过15秒，再返回列表 | 当前媒体/预览保持正确；旧超时或错误回调不覆盖它，无偷偷重播；记录切换前后媒体编号及等待后的界面 | NOT RUN |
| C09 | 错误页后台进程死亡后恢复 | 单独验证错误状态和重试可操作性；历史专项只测了普通后台往返，未覆盖此项 | NOT RUN |
| C10 | 人为制造连接保持但无响应的网络，再等待超时 | 仅在另行可控网络故障装置下执行；检查超时说明与取消。missing/invalid 不等价于网络无响应，现有 control 不提供该模式 | NOT RUN |

常用遥控命令（均是对专用测试设备的真实按键输入）：

```bash
adb -s <serial> shell input keyevent 23  # DPAD_CENTER / 确定
adb -s <serial> shell input keyevent 21  # 左
adb -s <serial> shell input keyevent 22  # 右
adb -s <serial> shell input keyevent 85  # MEDIA_PLAY_PAUSE
adb -s <serial> shell input keyevent 4   # Back
adb -s <serial> shell input keyevent 3   # Home
```

C04 可选用 README 中的 `video_smoke.py` 辅助截图/暂停/恢复；须人工预先播放合成 A/B 且余量超过15秒。它只允许模拟器，ROI 结果是启发式，不能替代本表判定，也不覆盖其他用例。

键盘按键命令耗时不是应用遥控延迟指标。无音频输出的模拟器只能确认视频帧/解码初始化，不能证明听感、音画同步或音频输出正确。

## F. 完成标准与已知未覆盖

- 每个 PASS 必须对应本轮 APK 与 profile 的实际证据；部分用例通过不写“全量通过”。检查最终 logcat 的 FATAL/ANR，并与操作时间对应。
- 收到失败响应到错误 UI 的时差仅是本轮观测，不对真实电视承诺绝对毫秒数；软件模拟器不做 FPS 基准。
- 自动 HTTP/生成器/JVM 测试通过，不替代上述 UI、真实帧推进、后台恢复与资源退出检查。
- 历史已跑范围见 README 候选表：整合 UI、收藏追加修复、视频专项不是同一个 APK 的全量复验。
- 默认未覆盖真实 NAS/电视、FN Connect真实网络发现、真实 token 过期、NAS 转码、4K/HEVC/HDR、多音轨/字幕、长视频、弱网/乱序全矩阵及长时间稳定性；需要单独授权环境和测试计划。
- 结束：正常退出应用/模拟器，Ctrl+C停止服务，记录剩余失败/未跑项；仅保留需要的合成证据，不提交状态、二进制和日志。

## 目标与决策

- 类型：新需求。
- 用户场景、当前问题与期望价值：用户要求完善幻灯片，减少遥控操作，连续观看当前浏览内容。
- 已确认：用户于 2026-11-02 对“播放间隔可选、循环播放、暂停/继续、选择是否播放视频；当前相册或当前列表、不做全库随机”回复“按照你的建议来”。
- 范围：上述四项；普通/共享相册与既有当前媒体列表；只在来源可证明完整或支持受控重启时循环整个范围。
- 非目标：随机排序、音乐、转场特效、投屏、后台自动播放、全图库无界缓存、NAS 写操作、依赖升级。
- 工程默认：间隔 3/5/10/15/30 秒，默认 5 秒；循环默认关、视频默认开。设备本地持久化这三项，但不持久化播放中状态。
- 从当前媒体起播，到末尾后循环回范围首项，不回最后驻留窗口；范围不完整/来源不支持可靠重启时明确说明并停止，绝不伪装完整循环。
- 禁用视频即跳过；启用视频即播完再推进，不受照片间隔截断。连续跳过最多175个媒体后暂停，显式继续方可刷新预算；源本身的五页扫描预算另行保留。
- 暂停照片后继续重新计完整间隔；视频暂停冻结帧，继续从当前位置播放。进后台停止自动播放，不自动续播。
- 照片确定键启动/暂停/继续，Menu 配置；视频操作栏提供幻灯片入口。设置打开时暂停，关闭仍暂停，明确“继续”才继续；Back 先关设置，详情Back退出。
- 单图允许开始并在间隔后结束，循环开启时持续展示；空列表提示会话失效；全视频且禁用视频时有限查找，不无限循环；图片失败沿用提示后推进，视频/分页失败停留可重试。
- 搜索/文件夹后续批、超限列表、地点不完整响应、进程死亡缺 live 源快照均不能冒充完整范围循环。
- 用户范围已确认；若需扩大原有搜索/文件夹分页上限或地点续页则另行澄清，不在本次隐式扩张。

## 交互、合同与兼容性

### 实现前基线行为（源码证据，不是设备验证）

- `MediaDetailActivity` 固定 `SLIDESHOW_INTERVAL=5000`。照片确定键启动，运行中确定键停止（无独立暂停状态），Back 停止并退出；照片快进键亦可启动。
- 主图加载成功或失败后开始完整间隔；缩略图完成不启动计时。当前图失败会提示并继续，视频失败停止幻灯片并显示持久重试 UI。
- 遇到视频自动播放，ExoPlayer/平台播放器 ended 回调切下一项，正常末尾停止。
- 视频左右定位、上下/Menu 操作栏；手动定位或显式切媒体目前会停止自动播放。新暂停/设置不能破坏视频的既有按键合同。
- `onStop` 失效图片/导航代数、释放播放器并停掉计时器；返回不自动恢复幻灯片。进程死亡只恢复有限媒体快照，没有 live 分页源。
- `MediaPageController` 有下一页、窗口前一页与边界回调，没有重启范围接口。普通主照片墙 560 原始行/16 页，详情最多 561 项；搜索/文件夹等原有 1,200 项边界保留。
- `MainFragment` PageSource 闭包捕获查询 generation，要求当前锚点仍能定位。直接清空列表/重跑 startPhotoPaging 会使旧 source 失效；循环不能简单把 currentIndex 置 0，也不能拼装无限列表。

### 交互

提供可聚焦的幻灯片配置/操作面板：间隔、循环、视频开关、开始/暂停/继续/结束。
每项都支持 DPAD/确定；面板显示时方向键交给实际控件焦点，不由详情吞掉；关闭后恢复媒体操作焦点。
照片缩放、信息层与视频定位/操作栏保持现有互斥规则。离开详情/进入后台终止自动推进，旧图片/分页/播放器回调不能重启。
暂停时清计时器并使旧自动导航回调代数失效；分页可能完成缓存交付，但不能越过暂停时当前媒体。
恢复时重新核对媒体 ID、有效 source 和用户意图；不得把准备完成当作允许自动播放。
已播完视频的待推进意图在分页等待/暂停间保留，继续时进入下一项而非重播；停止或换项清理。

### 分页与循环设计约束

- 复用 `MediaPageController` 与 list-owned `PageSource`；offset 仍按原始响应行数，不按过滤后的图片数推进。
- 只有明确完整结束且没有 boundary/incomplete 才允许新一轮；暂停、五页扫描预算、网络失败、超限、撤权和源失效不是结束。
- 若用户要求完整范围循环：为来源增加显式、可失败的“重启当前范围”能力。保持相同查询/相册身份、排序和权限，使用已证实 API 的 offset=0；这是客户端能力扩展，不是新 NAS 参数。
- 重启返回独立 replacement 结果，而非普通 ensureWindow 的“必须保留当前锚点”路径；单在途、代数、失败回退、返回列表定位均须测试。保留旧媒体直到新首项可交付，不在重启失败时跳到错误窗口。
- 无分页源但确知完整的有限列表可本地回首；源不完整或进程死亡恢复不能宣称全相册循环。
- 关闭视频只改变幻灯片选择，不改父列表筛选。连续跳过视频采用有界扫描，不能递归爆栈、耗尽请求或给每次回调补充预算。全视频列表不能不断重启。
- 跨轮 offset 重读依赖网络和 NAS 当前数据；不承诺删除/新增期间快照一致性、全局去重或离线循环。

### API、权限及真实 NAS 依赖

不新增猜测的 API。普通相册复用 `/p/api/v1/album/photos` 的 `album_id/sort_by/sort_direction/offset/limit`；日期媒体复用 `gallery/getList`；搜索/文件夹沿用各自现有合同。
共享复用 `/p/api/v1/album/normal/getList` 的 `albumId/startTime/endTime/offset/limit/sortDirection`，保持只读；不能替换成普通相册参数。
媒体播放沿用普通/共享不同传输路径与凭据重定向限制，15 秒视频等待上限、受限 fallback 均不放宽。

上述证据来自当前客户端源码/既有参考合同，不是本次真实 NAS 联调结果。
真实 NAS 尚需验证：重启 offset=0 与排序、末页 hasNext/缺字段语义、稀疏过滤、分页期间数据变化、共享撤权、媒体401、共享 Range 和真实设备解码。
地点续页、服务端 category 筛选无已证实合同；本需求不得顺带猜实现。仅配置与本地计时可脱离 NAS 测试；端到端完整范围循环不能只凭 mock 宣称兼容。

兼容性：保留 Java 8 / API19、AGP/Gradle/OkHttp/Leanback/Glide/ExoPlayer 现有版本。
安全/性能：无凭据日志、无私人媒体 fixture；有界元数据/图片预取，Glide 管线不自行 recycle；无全相册预加载。
依据：[实现约束](../development/constraints.md)、[开发流程](../development/workflow.md)、[设备 QA](../../test/QA_CHECKLIST.md)。

## 交付计划

1. 已取得用户四项范围确认并记录工程默认；范围变化先更新需求。
2. 按确认范围最小扩展状态：配置与会话运行/暂停/等待/结束分离；复用现有图片/视频/分页代数，不重写 MainFragment。
3. 接入TV面板与遥控，视频暂停意图和幻灯片意图协调；按确认范围扩展受控重启/跳过。
4. 同一候选 diff 并行执行自动化/设备验证与另一 agent 独立 review；review 覆盖正确性、分页资源上限、焦点、安全、API19、测试盲点；发现问题再修复重验复审。
5. 报告 `docs/reports/slideshow-enhancement.md`；合成截图/日志位于已忽略 `test/.generated/` 并提供可访问附件，标 commit、设备/API、APK SHA256。分开 PASS/FAIL/SKIPPED/NOT RUN/BLOCKED。
6. 适用测试与独立review通过后，按用户已确认的项目规范推送并创建Draft PR，核对远端SHA与CI；不合并、不部署。
7. 同步开发索引、遥控/大图库边界及QA文档；回退为撤销本需求实现提交，避免破坏已有配置/分页数据；不升级依赖。

剩余风险：完整范围循环与分页窗口耦合；稀疏跳过消耗扫描预算；变化数据集重读；混合媒体暂停状态；不完整来源无法证明全量。用户确认需求不替代真实NAS及设备验证。

# 年月快速跳转需求

## 目标与已确认决策

类型：新需求。用户希望在 Android TV 照片墙用遥控器快速查看指定年月，并能返回跳转前的位置。
本次会话已确认：提供“跳转年月”，先选年再选月；按所选月展示当前相册/人物/筛选来源的结果；
有已使用的日期接口就按月查询，普通相册可取消地分批扫描、显示进度并允许显式继续。
未读完不能声称没有照片。不采用全图库驻留内存或先递归读完再建立月份索引。

基线：2026-11-02 重新克隆并核对 main 为 `593e368b3f8c16608aa67d0c165c2ae2f968c71f`。
参考 [交互比较](https://github.com/ljmljz/fnphoto-tv/compare/main...ynwessnso:main) 仅作交互参考，
其全量加载/本地索引方案不在本次范围。

范围：主照片墙的图库日期、收藏日期、照片/视频筛选、普通相册、共享相册和人物日期来源。
日期墙中选中的单日是进入位置，跳月时替换单日范围，仍保留人物/相册 ID 和本地收藏/类型约束。
非目标：地点（无验证分页合同）、独立文件夹/搜索 Activity、目录级年月导航、标签/智能分类、
全图库随机索引、离线恢复、生产 NAS 兼容性认证、依赖升级。未支持来源明确提示，不伪称全部可用。

## 交互、合同与兼容性

- 主界面常驻可聚焦“跳转年月”入口；有效照片墙打开年份列表，再打开月份列表，DPAD/确定操作，
  Back 取消当前选择。无有效来源时解释限制。选择后标题显示目标年月。
- 扫描/请求中可再次选择月份或 Back；前者替换当前查询，后者恢复跳转前来源。
  “返回原位置”入口及 Back 都可恢复。仅保留一个来源 + 原始坐标 + 稳定 ID 恢复点，不保留列表快照或书签链。
- 恢复重新请求原来源的有限坐标范围；服务器删除/移动媒体、网络失败、进程死亡不能保证精确恢复。
  未找到原 ID 明确说明；月查询 offset 只能属于月来源，不能用于原来源恢复。
- 原始 offset、单请求在途、失败原 offset 重试、短非空页继续、五页自动扫描预算、
  560 原始行/16 页窗口、屏幕/详情最多 561 项、每响应 8 MiB 全部沿用。
  扫描暂停明确显示已查原始行数，可显式继续；只有完整有效终止证据才允许说该月没有匹配内容。
- 页面/月份变更先使代数失效再取消；后台暂停新年月工作，回来需显式继续；详情返回保留月份来源，
  抽屉/对话框打开期间不抢焦点。Java8、API19，不升级依赖。

| 来源 | 已使用客户端合同与本次策略 | 证据边界 |
| --- | --- | --- |
| 图库/日期/收藏/类型 | `gallery/getList` 的 `start_time/end_time/offset/limit/mode=index`；月首 00:00:00 至月末 23:59:59；收藏/类型继续本地判定 | FnHttpApi 与调用点；不是新增服务端 category/收藏参数 |
| 人物 | `ai-person/photoLibrary/list`，保留 personId、album_id 和大小写时间别名 | 现有客户端合同，按同样日期格式替换月份 |
| 共享 | `album/normal/getList` 的 albumId/startTime/endTime/offset/limit/sortDirection | 只读；月份不得超出现有 2000–2099 范围 |
| 普通相册 | `album/photos` 的 album_id/date_time 排序/offset/limit | 无已验证日期请求参数，按原始页扫描；严格使用日期 DTO 字段，标题/文件名不能作日期 |

月份采用服务器日期文本的年月，不把本地时区换算猜成服务器时区。普通相册接受可验证的
`photoDateTime` 拍摄日期文本；`dateTime` 在现有详情页可表示上传时间，不作为拍摄日期回退。
缺失/不合法的拍摄日期视为不能可靠分类，记录不完整，
扫描到末尾仍不能据此宣称不存在。数字时间戳单位、NAS 时区、两字段生产语义属真实联调待验证边界。
年份选择支持 1–9999 的有限分段/步进输入实现（共享仅 2000–2099）；无需加载全量日期索引。

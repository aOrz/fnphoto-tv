# 年月快速跳转

主界面顶栏及 MENU 抽屉中的“跳转年月”用于已经打开的分页照片墙。先进入图库日期、收藏日期、
人物日期、普通相册、共享相册或照片/视频筛选，再用遥控器选择年月。
本页说明客户端行为与边界；需求见 [年月导航需求](requirements/year-month-navigation.md)，
验证记录应以本次交付报告为准，不能从功能说明推断设备或真实 NAS 已验证。

## 遥控操作与范围

1. 聚焦“跳转年月”并按确定；深层照片墙可按 MENU，在抽屉中用 DPAD 选择该入口，
   不必向上重取所有旧页。年份界面可按 ±1 年、±10 年调整，再选择“选择月份”。
2. 用 DPAD 选择月份并按确定，照片墙显示所选月的结果。月份界面按 Back 返回年份，
   年份界面按 Back 取消选择；取消不会替换当前查询。
3. 月份结果、加载、暂停或空态中，可重新选择年月；“返回原位置”或照片墙 Back
   重新读取跳转前的来源和位置。连续跳月保留第一次跳转前的一个恢复点。
4. 遇到扫描预算暂停，选择“继续查找”或底部继续入口。未扫完会显示进度，
   不能把暂停或当前驻留窗口没有匹配当作整个月没有照片。

月份条件替换进入照片墙时的单日条件，保留相册或人物 ID、收藏判定和照片/视频筛选。
它不把单日与月份取交集，因此可以从一个日期跳到另一个月份。
年月功能不适用于日期/相册/人物等目录、最近添加、地点结果、独立文件夹或搜索 Activity；
主界面在不支持的来源打开入口时会说明限制。最近添加没有已验证的年月查询合同，
不能借用图库月份接口后把原范围扩大为全图库；也没有加入新的目录或搜索年月接口。

## 请求与日期语义

| 照片墙来源 | 月份查询方式 | 保留的约束 |
| --- | --- | --- |
| 图库日期、收藏日期、照片/视频筛选 | `gallery/getList` 的 `start_time/end_time/offset/limit/mode=index` | 收藏和媒体类型继续本地判定；不增加未验证的服务端筛选参数 |
| 人物日期 | `ai-person/photoLibrary/list` 的现有时间参数 | 保留 `personId`、`album_id` 与大小写时间别名 |
| 共享相册 | `album/normal/getList` 的 `startTime/endTime` | 保留 `albumId/offset/limit/sortDirection` 和只读规则；年份限制在 2000–2099 |
| 普通相册 | 原 `album/photos` 按原始页扫描，再匹配拍摄日期 | 保留 `album_id/sort_by=date_time/sort_direction/offset/limit`；不猜测日期过滤参数，不借用共享接口 |

服务端日期查询从月首 `00:00:00` 到月末 `23:59:59`，沿用 `YYYY:MM:DD HH:mm:ss`
文本格式，并计算闰年/月末。普通来源年份选择为 1–9999；共享默认完整范围仍为
`2000:01:01 00:00:00` 至 `2099:12:31 23:59:59`，跳月只在此范围内缩小请求。
这些是客户端已有合同与新调用行为，不证明 NAS 时区、范围外媒体或各版本兼容性。

普通相册只使用 `GalleryPhoto.photoDateTime`，严格接受完整有效的
`YYYY-MM-DD HH:mm:ss` 或 `YYYY:MM:DD HH:mm:ss` 拍摄日期文本。
`dateTime` 在现有详情页可表示上传时间，不作为拍摄时间回退；标题和文件名也不用于推算日期。
缺失值、非法日期、仅日期、时间戳、带时区或其他未验证格式归为未知。
扫描中出现未知日期会保留不完整提示；即使扫到末尾，也不能确认该月没有照片。
服务端按月查询的结果不再用这个本地日期规则二次过滤，避免猜测 NAS 的月份语义。

普通相册不会因为某页日期较早或较晚就提前结束，也不按排序二分定位。
`sort_by=date_time` 不能证明拍摄日期单调，未知日期也不能成为跳过尚未读取范围的依据。

## 有界扫描与取消

月份结果沿用 [大图库边界](large-library-boundaries.md)：普通照片页 35 行、共享页 50 行，
窗口最多 560 原始行/16 页，屏幕和详情最多 561 项（含一个稀疏锚点）。
不预先读完整个图库，不持有全量年月索引、完整列表快照或无界已访问 ID 集合。

一次自动需求最多请求五个原始页；无匹配的普通相册扫描耗尽预算后须显式继续。
进度按当前查询的原始行坐标计算，去重和本地筛选不改变 offset。
同一分页来源只有一个请求在途，失败重试原 offset；缺少 `hasNext` 时短非空页继续读取，
明确 `hasNext=false` 或有效的后续空页才给出终止依据。矛盾空页、重复页、超限或失败
保留错误/不完整状态。每响应 8 MiB 限制不变，也不表示进程总内存上限。

切换月份、切换来源或退出先使旧请求代数失效再取消，旧结果不能覆盖新查询。
后台停止年月扫描并显示暂停，回前台需显式继续；打开详情保留月份来源，详情停止时
通过 `PageSource` 的停止钩子取消该来源的工作。详情中的旧交付不能取走新请求的回调。
选择器与抽屉打开期间不能由异步加载抢焦点。具体焦点与生命周期验收需对应 APK 的设备证据。

## 返回原位置的边界

`MonthReturnPoint` 只保存一个恢复点：原来源参数、原查询的原始 offset、稳定媒体 ID，
不保存原照片列表。返回会恢复原来源，从原坐标之前最多两个页长的位置开始，
最多重新读取五页附近内容，并按 ID 定位；原来没有可选媒体时从原来源 offset 0 重新读取。
月查询的 offset 属于该月查询，不能当作原相册、原单日或原筛选的 offset。

未在有限范围找到原 ID 时明确提示原位置未能恢复，并保留原来源附近内容。
网络失败保留重试；照片删除、移动、筛选变化、短页或服务端数据变动都可能影响恢复。
没有服务器快照合同就不能承诺原坐标仍对应原照片，更不能以内存旧项代替重新读取结果。
恢复点只存在于当前浏览会话，进程死亡不保证恢复它；详情已有有限快照恢复也不等于恢复 live 分页来源。

## 实现与验证入口

- `MainFragment`：月份来源、扫描、取消、返回与详情交接。
- `YearMonthPicker`、`YearMonthRange`：DPAD 年月选择及日期边界/严格匹配。
- `MonthReturnPoint`：单个来源坐标；`SlidingPhotoWindow`、`MainPagingState` 保持现有分页预算。
- `YearMonthRangeTest`、`MonthReturnPointTest`、`MediaPageStopTest`：日期、恢复坐标和交付隔离的 JVM 测试。

构建、lint、Python 合同、设备截图及真实 NAS 验证分开记录，命令和证据要求见
[开发流程](development/workflow.md)。Java 8/API19 与固定依赖约束保持不变；
JVM 状态测试不能证明 TV 焦点、API19 运行时或真实 NAS 日期语义。

# 记住上次浏览类型

## 行为

- 记住最后一次**成功加载**的主浏览类型：图库、文件夹、收藏、最近添加、相册、人物、地点，以及媒体类型中的照片/视频。有效的空列表也算成功；分页类型以首个合法列表响应为准，不要求下载整个图库。
- 下次进入主页面直接加载该类型，不先加载图库；应用版本/统计查询是独立的可选请求，失败或延迟不能阻塞或覆盖浏览选择。详情、搜索、设置返回不会额外启动一次初始加载。
- 保存的是稳定类型 ID，不是菜单下标、中文标题、某个具体相册/人物、照片位置或未完成的操作。页面重建/进程重启恢复类型根目录，不承诺恢复到具体详情。
- 点击共享、标签、智能分类等未接入入口，仅显示原来的明确说明；不改当前类型，也不覆盖记忆。打开媒体类型后取消、打开搜索/设置也不覆盖。
- **共享相册仍未实现**：当前仓库缺少可验证的共享接口合同，不能把普通相册列表冒充共享相册。即使旧数据/人为写入 `shared`，也安全回到图库，清除无效类型；未来只有真正接入并验证后才能加入可恢复白名单。

## 账号、失败与遥控

- 使用 NAS 的用户输入源地址/FN ID + 用户名生成 SHA-256 标识，不使用令牌或密码作为键。FN ID 自动发现的新 IP、刷新令牌不会改变同一来源账号的标识；不同 NAS 或账号不相互套用类型。通过不同别名输入的同一 NAS 保守视为不同来源，不猜测它们相同。
- 已记住登录的旧安装可从已有来源/用户名迁移标识；旧会话如果缺少可验证的用户名则暂不保存全局类型，下次正常登录建立标识。是否勾选“记住登录”不影响本次会话的账号隔离。
- 退出登录清除该账号的类型和活动标识；之后抵达的旧成功回调不能重新保存。再次登录从图库开始。清理图片缓存不清理类型。
- 网络/HTTP/业务响应失败不能算“成功选择”。启动恢复失败时只尝试一次图库兜底并提示；**保留原类型**，避免短暂断网永久改偏好。图库也失败时提供遥控器“确定重试”卡和菜单入口，不循环请求；显式重新选择并成功加载后才改记忆。
- 主列表沿用请求代数取消/丢弃旧响应，快速切换不能让旧类型覆写新类型。打开菜单时定位到当前类型；照片/视频对应“媒体类型”菜单行。关闭菜单/加载完成后尝试将焦点交回内容；合法空列表回到可聚焦的“浏览”按钮，弹窗或菜单打开时不抢焦点。

## 检查

自动验证命令：

```sh
bash ./gradlew --no-daemon :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
python -m unittest discover -s test -p 'test_*.py' -v
```

`BrowseSelectionTest` 覆盖首次进入、所有支持类型、失败/旧回调、无效/未实现值、取消/非浏览入口、一次启动回退、手动重试、账号/NAS 隔离、退出清理、缺少身份，以及照片/视频的独立持久化 ID。

设备检查表（使用专用合成测试账号，不是真实私人相册）：

1. 选择相册，加载成功后退出/强制停止再启动：标题、内容及再次打开菜单的焦点均为相册；照片与视频分别重复。
2. 刚进入时延迟/让版本接口失败：类型列表仍加载，迟到版本响应不跳回图库。
3. 选择相册后，点共享、打开媒体分类再取消、打开搜索/设置返回；重新启动仍为相册。
4. 将根列表接口设为失败后重启：回退图库一次；继续失败时重试/菜单可达，不请求风暴；网络恢复后重启仍尝试原类型。
5. 先选人物再快速选相册，令人物响应最后到达：最终显示/保存相册；菜单关闭动画期间立即返回列表响应，确认焦点进入内容。
6. 有效空列表仍记住类型，“浏览”可聚焦；未知/`shared` 偏好退回图库。相册分页首请求失败不算成功，后续页失败不删除已经成功进入的类型。
7. 账号 A、账号 B 和另一 NAS 不串类型；退出登录后重新登录回图库；图片清缓存不重置类型。
8. 重建主 Activity 或进程被终止后再进入，不出现重复 Fragment 加载/空白；进入详情或设置再返回不会强制跳回根目录。

本实现的本地 JVM/构建/lint 验证不等于设备遥控焦点、真实 NAS 或 API19/TV 运行时已验证。没有连接的模拟器/电视时，上述设备矩阵必须记录为 **NOT RUN**，不能沿用旧 APK 的历史验证结果。

# 共享相册：接收方浏览

本次根据用户提供的《共享相册功能与接口交接》实现，基于 `main` 的
`26e6b76` 开始实现，并在 PR #6/#8 合并后重基至 `709871d`，保留新的大图库安全边界与按账号记忆类型；
不是将旧 `062a6fd` 的整份 Fragment 覆盖到新主线。
来源：<https://chatgpt.com/space/page_c86495314258819199a9dafd3054cf42>。
该页面是另一个客户端版本的静态交接，不是服务端正式协议或真实 NAS 联调记录。
后续用户提供的参考 APK（`com.fnphoto.tv`，versionName `1.0` / versionCode `1`）
静态核对确认了这两个 GET 端点、参数大小写、1000/50 页大小、固定时间范围、
DTO 字段和“拥有者 · N 项”卡片、“共享 · 相册名”标题；保留主线分页/取消机制，
不照搬旧版一次性目录加载或只按页长结束分页。参考 APK 也不是服务端兼容性证据。

## 已实现

- 菜单“共享”展示“分享给我”，请求独立的 `album_grant/list_to_me`，不会拿本人相册代替。
- 卡片展示名称、拥有者、非零项目数、封面。空值有占位，初始封面 URL 只接受相对地址或 NAS 同源绝对地址。
- 保留交接中的 `limit=1000` 与 `share_mod_time desc` 排序，按可选 `total` 续页；缺少或矛盾的总数继续按需请求至空页，不把无合同保证的短页冒充末页。偏移按服务端原始行数推进，显示 ID 去重，重复页停止。
- 进入相册使用 `album/normal/getList`，严格使用 `albumId/startTime/endTime/sortDirection`，每页 50 项；明确的 `hasNext` 优先，缺省继续至空页。不把含义未证实的 `count` 当作总量。
- 照片墙靠近末尾时遥控器焦点预取；底部可用遥控器确定/触屏点击“加载更多”或“重试”。不会进入后立即下载完整相册。
- 继承新主线 8 MiB 解压后元数据限制和 1200 项窗口；共享目录以完整的1000项页为单位，下一页放不下时由用户明确选择“下一批”替换当前批，不静默丢掉响应尾部。照片/视频每批最多1200项，详情边界提示返回列表续批。
- 图片使用文档 `/stream/p/t/{id}/s/{UUID}` 和 `/m/{UUID}`，不是原图；视频使用 `/stream/v/{id}`。缺少 UUID 不拼 `/null`，仅尝试响应中已有的同源缩略图地址。UUID 按一个路径段编码，拒绝 `.`/`..`。
- 复用主线图片、详情、幻灯片与分页查看器。共享视频采用流式 OkHttp 数据源，支持 Range/定位，不整文件缓存；共享模式不降级到无法约束认证重定向的平台 MediaPlayer。普通视频保持原流程。共享详情按返回键后，尝试按最后媒体 ID 恢复墙上焦点；再返回保留共享目录及原相册位置。
- 带 `accesstoken/authx` 的 OkHttp 请求逐跳拒绝跨协议/主机/端口重定向，包含同源后再转异源的多跳。安全拒绝不触发自动重连/重新登录，避免把凭据保护失败当普通网络故障重试。
- 初页/后续页错误有明确、可点击的重试状态，保留已加载内容和原 offset；复用 `MainRequestScope` 取消及丢弃过时响应。菜单换栏目后迟到的版本接口也不会覆盖用户已选栏目。
- **接收方只读**：共享详情中的收藏快捷键仅提示暂不支持，不调用未经确认的收藏写接口。未实现创建共享、邀请、成员管理或权限修改。
- 与新主线按账号记忆浏览类型整合：共享目录成功加载（包括合法空列表）后记住“共享”；失败、旧回调和取消不覆盖成功选择，启动恢复失败按主线规则回退图库，登出清除。没有保存类型的新用户仍默认图库，不照旧交接强制共享。

## 文档是否够用

**足够实现和合成验证接收方浏览；不足以承诺真实 NAS 全版本兼容，也不足以开发共享管理。**

联调仍需：

1. 目标 fnOS/相册服务版本；脱敏真实列表和内容成功响应，特别是 nullable 字段、ID 范围、`total/count/hasNext` 含义及服务端分页上限。
2. 固定 `2000:01:01 00:00:00` 至 `2099:12:31 23:59:59` 的时区、边界、范围外媒体处理。实现暂保留交接范围，不猜测“无限时间”参数。
3. 无共享/共享撤销/会话过期的 HTTP 与业务错误样本；共享图片、视频、详情权限，以及媒体 401/重试合同。
4. 创建分享、成员邀请、权限管理、共享媒体收藏的正式接口与权限语义。未从 DTO 名称或 `permission` 值推断这些能力。
5. 若 NAS 返回跨域封面/CDN/重定向，需要正式的媒体认证来源规则。当前初始 URL 限同源，且共享图片/视频使用的 OkHttp 在每一跳拒绝跨源认证重定向；不会为了兼容未知 CDN 转发 NAS 凭据。普通视频仍使用原播放器路径，本次不宣称其传输已改造。

去重与失败重试原始 offset。共享合成服务使用独立 albumId/媒体 ID，不混入本人相册，

所有自动/模拟器测试使用合成数据，只证明客户端与这份交接建模的一致性；
构建成功及 mock 成功不等同于真实 NAS 权限、签名或视频兼容性已通过。
